## Findings

- **The drift was not in the newest work.** `wallJoins.ts`, `stairPath.ts` and `cameraTour.ts`
  were all already indexed. What had never been indexed at all was the **older, unglamorous
  machinery**: `boqEngine.ts`, `blueprintExport.ts`, `modelLoader.ts`, `pathTracerEngine.ts`,
  `smartWallSnap.ts`, `aiFurnitureEngine.ts`, the whole graphics-settings surface, and on the
  backend `prompt_to_plan.py`, `envelope/envelope.py`, `demo.py` and `bench_stability.py`. Some
  of it shipped 2026-08-27. **A commit-by-commit vault update misses whatever was never
  interesting enough to write up**, and that accumulates silently. Fourteen modules, file-by-file.
- **Three code comments pointed at notes that do not exist.** Found by extracting every
  `notes/**.md` path mentioned in the source and testing each for a file:
  - `notes/decisions/zone-rule-is-a-constraint.md` — cited by `frontend/lib/stairPath.ts` and
    `backend/tests/test_model_blueprints.py`, stated as a hard rule in `CLAUDE.md`, and listed in
    [[Home]] as a locked decision with no link behind it. It had **never been created.** The
    project's most load-bearing rule existed only in code comments. Written today:
    [[zone-rule-is-a-constraint]].
  - `notes/findings/furniture-clearances.md` — wrong folder; the note is at
    `notes/architecture/furniture-clearances.md`. Pointer fixed in `clearances.ts`.
  - `notes/market/price-ceiling.md` — deliberately deleted with the rest of `notes/market/` in
    `07b01f2`. `quantities.py` still cited it for the Rs 3,000–5,000 ticket that sized the whole
    module. The citation now says the figure is unsourced and low-confidence rather than pointing
    at a file that is not there.
- **Three notes each carried a different test count** — `codebase-map` said 50/50,
  `backend/README.md` 173/173, `project-status` "139 passing, 1 failing". The real answer is
  **183, measured by running them.** This is the same failure [[knowledge-graph]] recorded for
  the node counts on 2026-08-31: read the number off the artefact.
- **The god components have grown every single month.** `Scene.tsx` is 89% larger than the day
  it was "structurized", `page.tsx` 146% larger. The graph says the same thing from the other
  side: 183 and 171 edges, the two highest in the repo. The 2026-08-30 seam pass bought one
  month, and the warning it left has been true and ignored ever since.

## Second half of the day — ponytail audit and fixes

`.agents/rules/ponytail.md` run mechanically over every source file, then the safe half of the
findings fixed on the user's instruction.

- **The BOQ was pricing a different building.** `quantities.py` measures the house off `walls.py`;
  the client ignored it and re-derived everything from room rectangles. Wall run **35% over**,
  bricks **42% under**, and total cost within 0.6% *because the errors offset* —
  [[boq-was-not-reading-the-takeoff]]. That coincidence is the reason it went unnoticed.
- **578 dead lines deleted.** `pathTracerEngine.ts` was a 198-line wrapper around a path tracer
  that `Scene.tsx` builds inline — written, then bypassed. Three components with zero references.
- **21 dead exports, 23 dead locals**, including eight materials allocated on every hall render
  and immediately shadowed by an identical set one branch below.
- **Collapsed** `escapeMarkup()` (3 copies), `downloadCsv()` (4 copies) and `newId()`
  (15 sites, 3 spellings).
- Net **−458 lines**. `tsc --noEmit` clean at every step, `next build` clean.

**Deliberately not fixed:** the 53 behavioural lint errors in `Scene.tsx` and
`Blueprint2DView.tsx`, and the three prompt parsers. The first needs eyes or tests, neither of
which exist; the second is a product decision.

## Findings, second half

- **A cleanup strands things too.** The re-lint found four texture caches and an import left
  behind by *this* pass's own deletions. Deleting something and not sweeping up after it is the
  same defect the audit was about, in miniature. Run the linter again after, not just before.
- **The pattern is one pattern.** A thing is built properly, a second copy is built beside it, and
  the good one is left wired to nothing. `walls.py` → the BOQ. The path tracer → its wrapper. The
  prompt parser → twice more. [[three-pickers]] and [[duplicated-geometry]] already named this
  class a month ago and it kept happening.
- **Shipping a correct number is half the job.** The other half is checking something reads it.
  `SolvedWall` has eight fields; the client typed all eight and read none.
- **Two offsetting errors look like a right answer.** The BOQ total was within 0.6% of correct
  while every material line under it was wrong. A single headline figure is not a check.
